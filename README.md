# 雙軌練習誌 · 健身 × 吉他

一個**純靜態**的個人習慣追蹤器。沒有後端、沒有資料庫、沒有任何套件 —— 只有 HTML / CSS / JavaScript，
直接雙擊 `index.html` 就能用，也能原封不動丟到 GitHub Pages。

## 功能

| 分頁 | 內容 |
| --- | --- |
| **總覽** | 每次打開隨機一句的激勵標語、**今天狀態教練**、兩軌各自的連續天數與最長紀錄、本週目標進度條、月曆熱力圖、近 12 週趨勢折線、12 枚成就徽章 |
| **吃什麼** | 用中文記三餐（「兩顆蛋加吐司配無糖豆漿」），自動粗估蛋白質與蔬菜，再依時間與已吃內容建議下一餐 |
| **打卡** | 可回頭補登任何一天。健身記部位／時長／強度；吉他記練習項目／時長／今天練的曲子 |
| **曲目** | 維護「正在練的歌」清單，五星熟練度，練成了標記完成 |
| **和弦工具** | 整首和弦譜一鍵升降調（歌詞不會被改到）、自動列出用到的和弦指法圖、變調夾建議、單一和弦查詢、各調級數表 |
| **設定** | 每週目標、體重與蛋白質目標、升降記號偏好、**自動備份到資料夾**、JSON 匯出／匯入 |

### 吃什麼

打開就會依「現在幾點 + 今天已經記了哪幾餐」自動選好下一餐，直接給 2～3 個具體選項。
例如早餐吃三明治、午餐吃雞腿便當，下午三點打開 → 它會跳到「點心」，
告訴你蛋白質還差多少、蔬菜今天掛零，然後建議「無糖豆漿 + 茶葉蛋」這種超商買得到的組合。

它會把這些一起算進去：今天有沒有訓練（有的話碳水不叫你少吃）、
吃到油炸或含糖的量、晚餐是不是太晚了。體重填了才算得出蛋白質目標（預設 1.6 g/kg）。

> **這是關鍵字比對，不是營養分析。** 它看到「雞腿便當」就估 25～32 g 蛋白質，
> 但實際份量每家店差很多，所以顯示的一律是範圍而不是單一數字。
> 當方向參考可以，不是醫療或營養建議；有體重控制或疾病需求請找營養師。
> 食物字典在 `js/meals.js` 的 `FOODS`，認不出來的東西自己加進去就好。

### 今天狀態教練

選一個今天的精神狀態（精力充沛／還可以／有點累／很累／生病受傷），
再勾選附加狀況（今天很忙／肌肉痠痛／手指痛／心情低落），
它會給你兩軌各自「今天做到這樣就夠了」的具體內容與分鐘數，按一下就把打卡表單填好。

設計上它**不會叫你休息了事**。很累的日子給的是「伸展 15 分鐘」和「彈最熟那首歌 5 分鐘」，
因為連續天數靠的是不要斷，不是每天都很猛。有連續紀錄時還會提醒你
「做完這 5 分鐘就保住了」。只有生病受傷時才會明確叫你停。

全部是寫死的規則運算，不連網、不呼叫任何 AI，離線也一樣會動。

│   ├── storage.js      ← 資料層：localStorage 讀寫、統計、徽章

## 在自己電腦上看

**最簡單**：用 Finder 雙擊 `index.html`。

> 少數瀏覽器在 `file://` 下會鎖住 localStorage，這時打卡會存不起來
> （程式偵測得到，會跳一行警告）。遇到的話改用下面的方式。

**比較保險**：在這個資料夾開終端機，起一個本機伺服器：

```bash
python3 -m http.server 4173
```

然後打開 http://localhost:4173 。按 `Ctrl + C` 結束。

## 上傳到 GitHub Pages

1. 在 GitHub 建一個新的 repository（例如 `habit-tracker`），**不要**勾選 Add a README。
2. 進 repo → `Add file` → `Upload files`。
3. 把這個資料夾**裡面的東西**整包拖進去 —— 也就是 `index.html`、`css/`、`js/`、`images/`。
   ⚠️ 不要把 `habit-tracker` 這層資料夾本身拖進去，否則網址會變成
   `你的帳號.github.io/habit-tracker/habit-tracker/`，而且 Pages 首頁會是空的。
4. 下方填個 commit 訊息（例如 `first upload`），按 `Commit changes`。
5. 進 repo 的 `Settings` → 左邊選 `Pages` →
   Source 選 **Deploy from a branch**，Branch 選 **main** + **/ (root)** → `Save`。
6. 等一兩分鐘，重新整理那一頁，上面會出現網址：
   `https://你的帳號.github.io/habit-tracker/`

之後要改東西，直接在 GitHub 網頁上編輯檔案，或重新 Upload 覆蓋即可，Pages 會自動重新部署。

### 容易踩的坑

- **檔名大小寫**：Mac 不分大小寫，GitHub Pages 會分。`Style.css` 和 `style.css` 在線上是兩個檔案。
- **路徑一律用相對路徑**：程式裡寫的是 `css/style.css`、`images/logo.svg`，
  不要改成 `/css/style.css`（開頭多一個斜線在 Pages 上會找錯位置）。
- **改了沒反應**：按 `Shift + 重新整理` 強制清快取。

## 資料存在哪裡？

存在你**這台電腦、這個瀏覽器**的 localStorage，鍵名是 `dualtrack.v1`，
包含打卡紀錄、每天的狀態與三餐、曲目清單、徽章與設定。

這代表：
- 資料不會上傳到任何地方，沒有人看得到（包括我）。
- 但是換電腦、換瀏覽器、清除瀏覽資料、用無痕模式，資料都會不見。
- 同一台電腦上，`file://` 開的和 `localhost` 開的和 GitHub Pages 開的，是**三份獨立的資料**。

### 自動備份（建議開啟）

到「設定 → 自動備份到資料夾」選一個資料夾，之後每次資料有變動，它就會自動寫兩個檔案進去：

- `dualtrack-backup.json` —— 最新的，每次覆蓋
- `dualtrack-2026-10-08.json` —— 當天的快照，萬一主檔寫壞還有得救

**把資料夾選在 iCloud Drive 或 Dropbox 裡面**，雲端硬碟就會順便幫你同步到其他裝置，
等於不用後端就有了備份加同步。換電腦時按「從資料夾還原」就全部回來。

限制：這個功能用的是瀏覽器的 File System Access API，
只有 **Chrome / Edge 桌面版**支援，而且要在 `https`（GitHub Pages）或 `localhost` 底下才能用，
直接 `file://` 雙擊開啟不行。不支援的環境會自動隱藏，改用下面的手動匯出，不會壞掉。

手機（iOS Safari）用不到這個，要同步還是得手動匯出／匯入一次。

另外程式啟動時會呼叫 `navigator.storage.persist()`，請瀏覽器不要在空間不足時把資料清掉。

## 想自己改的地方

| 想改什麼 | 改哪裡 |
| --- | --- |
| 配色 | `css/style.css` 最上面的 `:root { --fit / --gtr / --bg ... }` |

| 激勵標語 | `js/coach.js` 的 `SLOGANS` 陣列，想加想改直接動它 |
| 狀態教練的建議內容 | `js/coach.js` 的 `PLAN`（五種狀態的基礎處方）與 `MODIFIERS`（附加狀況怎麼調整） |
| 食物字典、餐點建議 | `js/meals.js` 的 `FOODS`（食物與蛋白質估值）與 `IDEAS`（建議清單） |

## 瀏覽器支援

Chrome / Edge / Firefox / Safari 的近幾年版本都可以。用到的都是標準 API
（localStorage、SVG、CSS Grid、Flexbox），沒有實驗性功能，也沒有連外網路請求。
